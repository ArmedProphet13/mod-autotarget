AutoTARGET

A quality-of-life modification that introduces modern action targeting to the WoW 3.3.5a client. It automatically directs your spells toward the enemy you are facing, eliminating the need to manually cycle targets before casting.

About

Modern action targeting comes to the WoW 3.3.5a client

Legacy targeting mechanics require manual tabbing or clicking before you can act, lagging behind modern standards. This quality-of-life modification updates the system: simply face your enemy and cast. Your spells automatically direct to the target you are aiming at, while leaving normal targeting, unit frames, and mouseover macros completely intact.

Install in 30 seconds

Two files. One folder. One checkbox

  1. 01

    Copy the files into your WoW folder

    Extract version.dll and AutoTarget.ini from the download and place them in the same folder as Wow.exe — the folder you launch the game from. 

    C:\Path\To\WoW\
  2. 02

    Start the game

    Open WoW and log into a character. The mod loads on its own — nothing to install, no extra clicks.

  3. 03

    Turn it on or off

    Open Interface Options → Combat. There's an Enable AutoTarget checkbox at the bottom — it's on by default. Tick it off any time to disable, or type /at on or /at off in chat.

Safety

Why a DLL, and how to verify it

Technical Architecture: Why a DLL?

Standard WoW addons are written in Lua and operate within a strict, sandboxed environment. While they can modify UI frames and monitor combat logs, they are entirely blocked from accessing or altering the core targeting engine. That logic resides deep within the compiled C++ executable, far beyond the reach of the Lua API.

Because true action targeting requires modifying these core routines, a traditional addon is mechanically insufficient.

AutoTarget is engineered as a lightweight version.dll library. It loads alongside Wow.exe at runtime, safely hooking into the client's internal targeting and casting routines.

How to verify the file you downloaded

Every release on the Releases page ships with a SHA-256 hash. Think of it as a fingerprint of the .zip — change one byte and the fingerprint changes completely. If the hash of your download matches the one published with the release, you're holding exactly the file we shipped.

Check it on Windows from any folder, no extra tool needed:

certutil -hashfile AutoTarget-v0.3.5.zip SHA256

Compare the output to the hash on the release page. They should match exactly.

A matching hash proves the file wasn't changed between us publishing it and you opening it. It does not prove the published file is safe — for that, the source has to be readable. It is: browse the code, or build it yourself with cmake --build . from the client/ folder. The DLL your build produces should be functionally identical to the one in the release.
